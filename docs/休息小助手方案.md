## 0. 定位与边界

- 本地离线单机工具：番茄式工作/休息提醒，托盘常驻
- 无联网、无账号、无数据上传；设置与统计数据仅存本机 userData
- 无外部图片/字体/CDN 资源，界面全部内联 SVG/CSS

## 1. 需求汇总（已确认）

| 项 | 结论 |
|---|---|
| 形态 | Electron 桌面程序：托盘驻留 + 迷你面板 + 提醒弹窗 |
| 目标平台 | Linux 开发运行 + electron-builder 出 Windows 便携版 .exe |
| 节奏 | 番茄式：默认工作 45min → 短休 5min，每 4 轮 → 长休 15min，全部可改 |
| 秒关 | ① 弹窗 `Esc`/`×` 立即关掉（跳过本次提醒）② 托盘「会议模式」提前静音 15/30/60min 或直到手动恢复 |
| 提醒样式 | 页内可爱弹窗：淡彩 + 手绘 SVG 团子猫，动画仅缓慢呼吸，默认静音、无声音 |
| 退出 | 关窗口 = 最小化托盘；真正退出走托盘菜单 |
| 数据 | 设置持久化 + 今日计数（工作轮数 / 休息次数 / 跳过次数） |

## 2. 总体架构

```
main.js（主进程，唯一状态源）
├── engine/pomodoro.js   番茄状态机（纯逻辑，零依赖，可单测）
├── engine/store.js      配置 / 断点 / 今日统计 JSON 持久化（userData 下）
├── windows.js            BrowserWindow 注册表（popup/panel/settings）
└── ui/*.html|js|css      各窗口页面；preload.js 做 contextBridge

数据流：引擎每秒 tick → webContents.send('state') → 各窗口只渲染、不持有状态
用户操作 → preload.invoke(cmd) → main.js 调引擎方法
```

引擎放主进程的原因：所有窗口全关后提醒照常触发；进程重启可从断点续跑。

## 3. 功能规格

### 3.1 番茄状态机

状态：`idle | work | short | long`；附加标记：`pause`（倒计时冻结）、`mute`（会议模式）、`awaiting`（等用户决策）。

- 时间一律用绝对截止时间戳（deadline），系统休眠/杀进程重启都不丢进度
- 完成一轮工作 → `round+1`；`round % 4 == 0` 下次进长休，否则短休
- **工作结束** → 弹窗，三选一：
  - `去休息` → 进入短/长休倒计时
  - `稍后 5 分钟` → 5 分钟后重复同一弹窗
  - `跳过本次` → 立刻开始下一轮工作，计入「跳过次数」
  - **等决策期间（弹窗挂着没点，含「稍后」等待、会议模式压住不弹）这段时间仍算工作时长**；面板圆环转橘红（`--over: #e2703a`）并保持满环，时钟显示递增的「已超时 mm:ss」。点「去休息」/「跳过休息」后立即停止累计
  - **休息结束后的等待点击期间不算工作时长**（那是在休息）
- **休息结束** → 弹窗询问（`开始工作` / `再休息 5 分钟`）。**永不自动开始工作**（v1.5 起移除「休息后自动开始」设置项）
- **暂停**（面板/托盘「开始/暂停」）= 冻结整个倒计时，恢复后接着走
- **会议模式**（提前静音）= 时钟照常走、但不弹任何提醒；提前到期自动恢复并托盘告知，也可随时手动恢复；恢复时若有积压提醒则照常弹出
- **设置修改**即时生效部分：立即对下一阶段生效，当前已开始的阶段沿用旧时长

### 3.2 托盘

- 图标 + tooltip 每秒刷新：如「工作 44:12 · 今日休息 3 次」「休息中 3:45」「会议模式 29:51」「已暂停」
- 单击开合迷你面板；右键菜单：开始/暂停、跳过本次休息、会议模式（15/30/60/手动）、设置、退出

### 3.3 窗口

| 窗口 | 尺寸 | 说明 |
|---|---|---|
| popup 提醒弹窗 | 380×352 | 无边框自定义标题栏（可拖动 + ×）；四种场景：① 每日首次「开始工作」确认 ② 工作结束（去休息/稍后/跳过）③ 休息进行中（倒计时 + 提前结束）④ 休息结束询问。Esc 秒关 |
| panel 迷你面板 | 340×556 | 进度环 + mascot 表情 + 今日计数 + 开始/暂停 + 会议模式 + 设置入口；skipTaskbar |
| settings 设置 | 372×560 | 工作时长/短休/长休/第几轮后长休/时长生效时机/开机自启。**注意：「开机自动启动」仅在 Windows 上真正生效**——Electron 的 `app.setLoginItemSettings` 在 Linux 是空操作（实测传 true 读回仍是 false、且不写任何 autostart 文件），Linux 上该勾选框目前只落库不生效，属已知未实现项 |

文案基调示例：「工作 45 分钟啦，喝口水，看看远处～」「眼睛累了就闭一会儿，我帮你看着时间」

### 3.4 持久化（userData 下）

- `config.json`：全部设置
- `state.json`：当前阶段、deadline、轮次、awaiting、snooze/mute 截止时间；阶段切换与每 30s 落盘；重启按 deadline 恢复，过期则立即触发对应提醒
- `stats.json`：今日计数（`day` 字段跨天自动重置）

## 4. 升级预留（v2 桌宠，v1 只铺路、不实现）

- `windows/` 注册表式管理：以后新增 `pet.js`（全屏透明+无边框+置顶+鼠标穿透）与 `walk.js`（全屏透明提醒层）零改动现有代码
- 引擎事件统一 IPC 广播，桌宠可订阅：上班=趴桌睡、到点=伸懒腰/走动引你休息
- 配置键预留：`pet.enabled`、`reminderStyle: 'popup'|'walk'`；素材目录 `ui/assets/pet/`
- 素材管线（v2 时再做）：真猫照片 → AI 生成多姿势 → ffmpeg 切帧 → sprite sheet → CSS `steps()` 播放；备选 Live2D（效果最好但要 rig，成本高一个量级）

## 5. 任务拆分与里程碑

| 里程碑 | 内容 |

| M1 骨架 | package.json、electron 安装、图标生成脚本（Node 内置 zlib 画 mascot 图标）、窗口注册表 + 托盘 |
| M2 引擎 | pomodoro.js 状态机 + store.js + `node --test` 状态机用例 |
| M3 界面 | popup / panel / settings 三窗 + 提醒流程 + 秒关 + 会议模式闭环 |
| M4 交付 | 持久化 + 断点续跑 + Linux 人工验证 + Windows 便携版打包 |

## 6. 验证方式

- `npm test`：引擎状态机单测（阶段切换、跳过、稍后、冻结/恢复、静音恢复、断点恢复）
- `npm start`：Linux 人工过一遍——正常一轮、Esc 秒关、会议模式静音/恢复、杀进程重启续跑、跨天重置
- `npm run dist:win` → 便携版 .exe；`npm run dist:linux` → AppImage

## 7. 风险

- Electron 首次安装约 100MB+ 下载（已确认网络可用；**打包时须先设 `ELECTRON_MIRROR`**，见 AGENTS.md）
- Windows 透明窗毛边 / 多屏定位：v2 桌宠时用 screen 模块 + 背景 alpha 处理
- 打包体积 100MB 级：便携版单文件即用，可接受
- **「开机自动启动」仅 Windows 生效**：Electron 的 `setLoginItemSettings` 在 Linux 是空操作，勾选只落库。要在 Linux 支持需自行写 `~/.config/autostart/*.desktop`，当前**未实现**
- **Windows 便携版真机未完整验证**：托盘右键菜单、透明窗毛边、开机自启三项均只在 Linux 侧推断，未在 Windows 真机确认过
